# Internacionalização (i18n)

> **Árvore:** [docs](../README.md) › [architecture](README.md) › i18n
> **Resumo:** Dicionário global vs. dicionários por tela, `defineMessages`, `translateDom`, `onLangChange` e o passo a passo para adicionar um texto.
> **Código:** `src/i18n/index.ts`, `src/i18n/en.ts`, `src/i18n/pt-BR.ts`, `src/screens/*/i18n.ts`, `src/screens/settings/{backup,strava}-i18n.ts`

## Idiomas

`type Lang = 'en' | 'pt-BR'`. Detecção inicial (`detectLang`):

1. `localStorage['lapwing:lang']` se for `en` ou `pt-BR`;
2. senão `navigator.language` começando com `pt` → `pt-BR`;
3. senão `en`.

`setLang(next)` grava em `lapwing:lang`, atualiza `<html lang>` e chama todos os listeners de `onLangChange`. O `<select id="lang">` do shell é quem normalmente chama `setLang`; a restauração de backup também (ver [storage-and-migration.md](storage-and-migration.md)).

## Dicionários

| Escopo | Arquivo | Tradutor | Tipo de chave |
|---|---|---|---|
| Global: shell, menu, tema, diálogos de confirmação, editor de rotas, toasts de GPX | `src/i18n/en.ts` + `src/i18n/pt-BR.ts` | `t` de `src/i18n` | `MessageKey = keyof typeof en` |
| Análise (activity) | `src/screens/activity/i18n.ts` | `tr` | `ActKey` |
| Comparação | `src/screens/compare/i18n.ts` | `tr` | `CmpKey` |
| Histórico | `src/screens/history/i18n.ts` | `t` (local) | — |
| Insights | `src/screens/insights/i18n.ts` | `t` (local) | `InsightsKey` |
| Treinos | `src/screens/training/i18n.ts` | `t` (local) | — |
| Configurações / backup | `src/screens/settings/backup-i18n.ts` | `tb` | `BackupKey` |
| Configurações / Strava | `src/screens/settings/strava-i18n.ts` | `tr` | `StravaKey` |
| Tênis (tela desativada) | `src/screens/gear/i18n.ts` | `t` (local) | `GearKey` |

Observações:

- O editor de rotas (`screens/routes`) não tem dicionário próprio: usa o global.
- A seção de aparência e o título da página de configurações também usam o global (`appearanceTitle`, `themeSystem`, `navSettings`…).
- Telas que precisam de textos globais importam `t` com outro nome (ex.: `t as tg` em `backup-section.ts`) para não colidir com o tradutor local.
- `pt-BR.ts` é tipado como `Record<MessageKey, string>`: esquecer uma chave quebra o `tsc`. Os dicionários por tela seguem o mesmo padrão (`const ptBR: Record<keyof typeof en, string>` ou `defineMessages<Key>`).

## API (`src/i18n/index.ts`)

| Export | Descrição |
|---|---|
| `getLang()` | Idioma atual |
| `setLang(lang)` | Troca, persiste e notifica |
| `onLangChange(fn)` | Assina; retorna função que cancela (use no cleanup da tela) |
| `defineMessages({ en, 'pt-BR' })` | Cria um `Translator<K>` para um par de dicionários |
| `t` | Tradutor global (`defineMessages({ en, 'pt-BR': ptBR })`) |
| `translateDom(root, tr)` | Preenche textos estáticos a partir de atributos `data-i18n*` |
| tipos | `Lang`, `MessageKey`, `Params`, `Translator<K>` |

### `defineMessages` e parâmetros

```ts
const tr = defineMessages({ en: { saved: 'Saved {count} runs' }, 'pt-BR': { saved: '{count} corridas salvas' } });
tr('saved', { count: 3 });
```

- Interpolação: `{nome}` é trocado por `params.nome`; placeholders sem parâmetro ficam como estão.
- Fallback: `dicts[lang][key]` → `dicts.en[key]` → a própria chave.
- O tradutor lê o idioma **a cada chamada**, então basta re-renderizar após `onLangChange`.

### `translateDom`

| Atributo | Efeito |
|---|---|
| `data-i18n="key"` | `textContent` |
| `data-i18n-title="key"` | `title` **e** `aria-label` |
| `data-i18n-placeholder="key"` | `placeholder` |

Usado pelo shell (`renderNav`), pelo editor de rotas e pela página de configurações. A maioria das telas renderiza com template strings chamando `tr(...)` diretamente e re-renderiza tudo em `onLangChange`.

## Formatação dependente do idioma (`src/format.ts`)

`formatDistance`, `formatNumber`, `formatDate`, `formatDateTime` usam `Intl` com `getLang()`. `formatDuration` e `formatPace` são neutros (`h:mm:ss`, `m:ss /km`). `parsePace` aceita `5:30` ou minutos decimais com `.` ou `,`.

## Como adicionar um texto

1. Decida o escopo: shell/editor de rotas → global; texto de uma tela → dicionário da tela.
2. Adicione a chave em **`en` e `pt-BR`** (o tipo obriga os dois).
3. Use:
   - em template: `${tr('minhaChave')}` (escape com `esc` se houver texto do usuário nos parâmetros);
   - em HTML estático: `<span data-i18n="minhaChave"></span>` + `translateDom(root, tr)`.
4. Se a tela fica montada enquanto o idioma muda, assine `onLangChange` e re-renderize; devolva o cancelamento no cleanup.
5. Rode `npm run typecheck`.

Para um novo item de menu, a chave do rótulo vai no dicionário global (`NAV_ITEMS[].label: MessageKey`). Ver [adding-a-screen.md](../development/adding-a-screen.md).
